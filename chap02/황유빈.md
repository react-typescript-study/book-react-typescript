### null 과 undefined 차이
```ts
type  Person1 ={
  name:stirng;
  job?:string
}

type Person2 ={
  name:string;
  job: string | null;
}
```

Person1 은 job 이라는 속성이 있을 수도 또는 없을 수도 있음을 나타낸다. 즉 job 이라는 속성 유무를 통해 무직인지 아닌지 나타낸다, Person2는 job 이라는 속성을 사람마다 갖고 있지만 값이 비어있을 수도 있다는 것을 나타낸다.  따라서 명시적인 null 값을 할당해 무직인 상태를 나타낸다고 볼 수 있다. 

### 점진적 타입 확인 이란?
컴파일 타임에 타입을 검사하면서 필요에 따라 타입 선언 생략을 허용하는 방식이다.
타입을 지정한 변수와 표현식은 정적으로 타입을 검사하지만 타입 선언이 생략되면 동적으로 검사를 수행한다.


### symbol 타입이란?

어떤 값과도 중복되지 않는 유일한 값을 만든다.

```ts
const MOVIE_TITLE = Symbol('title')
const MUSIC_TITLE = Symbol('title')
console.log(MOVIE_TITLE === MUSIC_TITLE); // false

let SYMBOL: unique symbol = Symbol()
```

같은 문자열 `title`을 넘겼는데도 서로 다른 값이 나온다. 다만 `Symbol()`과 `Symbol.for()`는 동작이 다르다.

```ts
Symbol('title') === Symbol('title');         // false — 호출할 때마다 새 값
Symbol.for('title') === Symbol.for('title'); // true  — 같은 키면 같은 값을 돌려줌
```

### symbol은 실무에서 어디에 쓰일까?

이미 우리가 쓰는 JSX 안에 symbol이 들어 있었다. `<div className="box">hi</div>`는 컴파일되면 아래 객체가 된다.

```js
{
  $$typeof: Symbol.for('react.element'),
  type: 'div',
  props: { className: 'box', children: 'hi' },
  key: null,
  ref: null,
}
```

`$$typeof`는 "React가 만든 진짜 엘리먼트"라는 표식이다. 처음에는 엘리먼트끼리 구분하려고 symbol을 쓰는 줄 알았는데, 모든 엘리먼트가 **같은 값**을 갖는다. 구분이 아니라 **위조 방지**가 목적이다.

- React 엘리먼트는 평범한 객체라서, 서버 응답 JSON이 같은 모양을 흉내 내면 엘리먼트로 오인할 수 있다.
- 엘리먼트로 인정되면 React는 `dangerouslySetInnerHTML` 같은 내용을 그대로 신뢰하므로 XSS로 이어진다.
- symbol은 JSON으로 표현할 수 없기 때문에 외부 데이터는 절대 `$$typeof`에 진짜 symbol을 넣을 수 없다.
- React가 두 벌 로드되거나 iframe을 넘어도 같은 값이어야 하므로 `Symbol()`이 아니라 `Symbol.for()`를 쓴다.

그 외 사례: `Symbol.iterator` 같은 well-known symbol로 객체에 `for...of` 프로토콜 부여, `unique symbol`로 브랜드 타입 만들기, `undefined`와 구분되는 "값 없음" 센티널, DI 토큰.

### enum 이란?

런타임에 실제 객체로 변환되는 값이다. TS가 JS에 없는 코드를 생성하는 몇 안 되는 문법이다.

```ts
enum Color { Red = 'RED', Blue = 'BLUE' }
// 컴파일 결과
var Color;
(function (Color) {
  Color["Red"] = "RED";
  Color["Blue"] = "BLUE";
})(Color || (Color = {}));
```

### enum vs `as const` 객체

```ts
export const Color = { Red: 'RED', Blue: 'BLUE' } as const;
export type Color = (typeof Color)[keyof typeof Color]; // 'RED' | 'BLUE'
```

| | `enum` | `as const` 객체 |
|---|---|---|
| 런타임 코드 | TS가 생성 (IIFE) | 순수 JS |
| 타입 | 명목 — `paint('RED')` 거부 | 구조 — `paint('RED')` 허용 |
| Babel/esbuild/`erasableSyntaxOnly` | 제약 있음 | 문제 없음 |
| 트리셰이킹 | 약함 | 잘 됨 |

API 응답이나 라우트 파라미터처럼 외부에서 문자열이 들어오는 자리가 많은 React 프로젝트에서는 `as const` 패턴이 기본값으로 쓰인다. enum은 "반드시 이 상수를 거쳐서만 값을 만들게" 강제해야 할 때 정도에 남는다.
