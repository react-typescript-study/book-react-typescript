## 리액트 컴포넌트의 타입

JSX 는 자바스크립트 안에서 UI 를 표현하는 문법이다. JSX 를 포함한 타입스크립트 파일은 `.tsx` 확장자를 사용한다. TSX 로 옮기면 컴포넌트에 전달하는 props, 이벤트, 반환값의 타입을 컴파일타임에 검사할 수 있다.

### 클래스 컴포넌트 타입

클래스 컴포넌트는 `React.Component<Props, State>` 또는 `React.PureComponent<Props, State>` 를 상속한다. 첫 번째 제네릭은 props, 두 번째는 state 의 타입이다.

```tsx
import * as React from "react";

interface CounterProps {
  label: string;
}

interface CounterState {
  count: number;
}

class Counter extends React.Component<CounterProps, CounterState> {
  state: CounterState = { count: 0 };

  render() {
    return (
      <button
        onClick={() => this.setState(({ count }) => ({ count: count + 1 }))}
      >
        {this.props.label}: {this.state.count}
      </button>
    );
  }
}
```

`this.props.label` 은 `string`, `this.state.count` 는 `number` 로 검사된다. `PureComponent` 도 타입을 지정하는 방법은 같고, props 와 state 를 얕게 비교해 불필요한 렌더링을 건너뛰는 동작이 추가된다.

### 함수 컴포넌트 타입

함수 컴포넌트는 매개변수에 props 타입을 붙이거나 `React.FC<Props>` 로 함수 전체의 타입을 지정한다.

```tsx
interface GreetingProps {
  name: string;
}

function Greeting({ name }: GreetingProps) {
  return <p>{name} 님, 안녕하세요.</p>;
}

const GreetingWithFC: React.FC<GreetingProps> = ({ name }) => {
  return <p>{name} 님, 안녕하세요.</p>;
};
```

매개변수에 타입을 붙이면 반환 타입은 구현에서 추론된다. 반환값을 제한할 필요가 있을 때는 `React.ReactElement | null` 처럼 명시할 수도 있다.

> 도서에 나오는 예전 `React.FC` 는 `children` 을 암묵적으로 포함했고, 이를 포함하지 않는 `React.VFC` 도 사용했다. **React 18 타입 정의부터는 `FC` 도 `children` 을 자동으로 추가하지 않는다.** `VFC` 는 deprecated 되었으므로 새 코드에서는 일반 함수나 `FC` 를 쓰고, `children` 이 필요하면 직접 선언한다. [React 18 타입 정의](https://github.com/DefinitelyTyped/DefinitelyTyped/blob/master/types/react/v18/index.d.ts)

### children props 타입 지정하기

`children` 으로 문자열, 숫자, JSX, 여러 자식 등을 받을 수 있다면 `React.ReactNode` 를 쓴다.

```tsx
interface PanelProps {
  title: string;
  children: React.ReactNode;
}

const Panel = ({ title, children }: PanelProps) => (
  <section>
    <h2>{title}</h2>
    {children}
  </section>
);
```

`React.PropsWithChildren<P>` 는 기존 props 에 선택적인 `children` 을 추가하는 유틸리티 타입이다.

```tsx
type OptionalPanelProps = React.PropsWithChildren<{ title: string }>;

// 위 타입의 핵심 구조
type OptionalPanelPropsExpanded = {
  title: string;
  children?: React.ReactNode;
};
```

자식 전달을 필수로 요구하려면 `children` 을 직접 필수 속성으로 선언한다. 다만 `ReactNode` 자체에 `null` 과 `undefined` 가 포함되므로, 필수 속성이라고 해서 화면에 보이는 내용까지 보장하는 것은 아니다.

### render 메서드와 함수 컴포넌트의 반환 타입

클래스의 `render` 와 함수 컴포넌트는 리액트가 렌더링할 값을 반환한다. 관련 타입은 비슷해 보여도 표현하는 범위가 다르다.

| 타입 | 의미 | 주로 사용하는 곳 |
| --- | --- | --- |
| `React.ReactElement<P>` | `type`, `props`, `key` 를 가진 리액트 엘리먼트 객체 | 엘리먼트의 props 타입까지 다룰 때 |
| `JSX.Element` | JSX 표현식의 결과 타입. 리액트에서는 `ReactElement` 기반 | JSX 를 반환하는 함수의 반환 타입 |
| `React.ReactNode` | 엘리먼트, 문자열, 숫자, 빈 값, 노드들의 컬렉션 등을 포함하는 넓은 타입 | 자유로운 `children` 이나 렌더링할 내용 |

`ReactElement` 는 실제 DOM 노드인 `HTMLElement` 와 다르다. `<button />` 은 리액트 엘리먼트를 만들고, 버튼 DOM 에 접근하는 ref 는 `HTMLButtonElement` 타입으로 다룬다.

도서에서 설명하는 과거 함수 컴포넌트 타입은 반환값을 `ReactElement | null` 로 제한했다. 이후 타입 정의와 타입스크립트 버전에 따라 허용 범위가 넓어졌으므로, **`ReactNode` 를 반환하는 함수는 언제나 컴포넌트로 쓸 수 없다고 단정하면 안 된다.** 실제 프로젝트의 `typescript` 와 `@types/react` 버전을 함께 확인한다.

> React 19 타입 정의에서는 전역 `JSX` 대신 `React.JSX` 를 사용한다. 도서의 `JSX.Element` 를 현재 환경에서 명시하려면 `React.JSX.Element` 로 쓸 수 있다. 또한 `ReactElement` 의 props 제네릭 기본값이 `any` 에서 `unknown` 으로 바뀌었다. [React 19 타입 변경 사항](https://react.dev/blog/2024/04/25/react-19-upgrade-guide#typescript-changes)

### ReactElement, ReactNode, JSX.Element 활용하기

자유로운 내용을 받는 슬롯에는 `ReactNode`, 하나의 엘리먼트 객체를 다루는 곳에는 `ReactElement` 를 선택한다.

```tsx
interface IconProps {
  size: number;
}

interface MenuItemProps {
  label: React.ReactNode;
  icon: React.ReactElement<IconProps>;
}

const MenuItem = ({ label, icon }: MenuItemProps) => {
  // props 제네릭을 지정했으므로 size 는 number 로 다룬다
  const iconSize = icon.props.size;

  return (
    <li style={{ minHeight: iconSize }}>
      {icon}
      {label}
    </li>
  );
};
```

`ReactElement<IconProps>` 는 컴포넌트 내부에서 `icon.props` 를 다룰 때 유용하다. 다만 JSX 표현식의 결과에서 구체적인 props 정보가 지워질 수 있어, **특정 컴포넌트만 자식으로 전달하도록 완전히 제한하는 장치는 아니다.** 이런 제약이 중요하면 `size` 같은 데이터를 props 로 받아 내부에서 아이콘을 만드는 방식도 고려한다. [리액트의 children 타입 설명](https://react.dev/learn/typescript#typing-children)

### 리액트에서 기본 HTML 요소 타입 활용하기

기본 HTML 속성을 직접 다시 선언하면 `disabled`, `type`, 이벤트 핸들러 같은 속성을 빠뜨리기 쉽다. 리액트가 제공하는 타입을 재사용하면 된다.

```tsx
type NativeButtonProps = React.ComponentPropsWithoutRef<"button">;

interface ButtonProps extends NativeButtonProps {
  variant?: "primary" | "secondary";
}

const Button = ({ variant = "primary", ...props }: ButtonProps) => (
  <button {...props} data-variant={variant} />
);
```

- `React.ButtonHTMLAttributes<HTMLButtonElement>`: 버튼의 HTML 속성과 이벤트 타입
- `React.DetailedHTMLProps<React.ButtonHTMLAttributes<HTMLButtonElement>, HTMLButtonElement>`: HTML 속성에 `key`, `ref` 같은 클래스 속성을 결합한 타입
- `React.ComponentPropsWithoutRef<"button">`: 버튼 props 에서 `ref` 를 제외한 타입
- `React.ComponentPropsWithRef<"button">`: 버튼 props 에 `ref` 를 포함한 타입

`ref` 를 받지 않는 래퍼 컴포넌트에는 `ComponentPropsWithoutRef` 를 쓰는 편이 의도가 분명하다. **타입에 `ref` 를 포함시키는 것만으로 실제 DOM 까지 연결되지는 않는다.**

도서에서 다루는 React 18 이하의 함수 컴포넌트는 `forwardRef` 로 ref 를 받아 전달한다.

```tsx
const ForwardedButton = React.forwardRef<HTMLButtonElement, ButtonProps>(
  ({ variant = "primary", ...props }, ref) => (
    <button {...props} ref={ref} data-variant={variant} />
  )
);
```

클래스 컴포넌트에 붙인 ref 는 클래스 인스턴스를 가리키고, 위 예제에서 전달한 ref 는 내부 버튼 DOM 을 가리킨다. `forwardRef` 의 제네릭 순서는 **ref 대상 타입, props 타입** 이다.

> React 19 에서는 함수 컴포넌트가 `ref` 를 prop 으로 받아 내부 요소에 전달할 수 있어 `forwardRef` 가 필수는 아니다. 위 코드는 도서의 전달 방식을 이해하기 위한 예제다. [리액트 forwardRef 문서](https://react.dev/reference/react/forwardRef)

## 타입스크립트로 리액트 컴포넌트 만들기

### JSX 로 구현된 Select 컴포넌트

선택지 객체의 키는 내부 값, 객체의 값은 화면에 보여줄 이름이라고 가정한다.

```tsx
const fruits = {
  apple: "사과",
  banana: "바나나",
  blueberry: "블루베리",
};
```

자바스크립트만 쓰면 `selectedOption="orange"` 처럼 선택지에 없는 값을 넘기거나, `onChange` 에 잘못된 인자를 받는 함수를 넘겨도 실행 전에는 알아채기 어렵다. TSX 로 전환할 때는 이 관계를 타입으로 표현하는 것이 핵심이다.

### JSDoc 으로 일부 타입 지정하기

자바스크립트를 유지해야 하는 상황에서는 JSDoc 으로 props 구조와 함수 인자를 설명할 수 있다.

```js
/**
 * @param {{
 *   options: Record<string, string>,
 *   selectedOption?: string,
 *   onChange?: (selected: string | undefined) => void
 * }} props
 */
function describeSelect(props) {
  return props.options;
}
```

JSDoc 은 에디터의 자동완성과 타입 정보에 도움을 준다. 자바스크립트 파일의 타입 오류도 검사하려면 `checkJs` 또는 파일의 `// @ts-check` 를 사용한다. TSX 로 옮기면 타입을 코드에서 직접 선언하고 재사용할 수 있다.

### props 인터페이스 적용하기

우선 props 의 기본 형태부터 선언한다.

```ts
interface SelectProps {
  options: Record<string, string>;
  selectedOption?: string;
  onChange?: (selected: string | undefined) => void;
}
```

`onChange?` 는 콜백 자체를 생략할 수 있다는 뜻이다. 인자의 `string | undefined` 는 콜백이 호출될 때 선택값이 없을 수도 있다는 뜻으로, 서로 다른 조건이다.

하지만 아직 `selectedOption` 은 모든 문자열을 받는다. props 에 타입을 붙이는 것만으로 `options` 와 선택값 사이의 관계까지 표현되지는 않는다.

### 리액트 이벤트 타입 지정하기

이벤트 핸들러를 함수로 분리하면 이벤트 종류와 대상 요소의 타입을 지정한다.

```tsx
const handleChange: React.ChangeEventHandler<HTMLSelectElement> = (event) => {
  const value = event.currentTarget.value;
  console.log(value); // string
};

// 매개변수에 직접 타입을 붙여도 된다
const handleChangeWithEvent = (
  event: React.ChangeEvent<HTMLSelectElement>
) => {
  console.log(event.currentTarget.value);
};
```

`currentTarget` 은 핸들러가 연결된 요소를 가리킨다. DOM 에서 읽은 `value` 는 문자열이므로, 선택지 키의 유니온 타입으로 쓰려면 실제 선택지와 대조하는 과정이 필요하다.

### 훅에 타입 추가하기

상태를 `string` 으로만 선언하면 선택지에 없는 문자열도 저장할 수 있다. 원본 객체에서 키 타입을 뽑아 상태에 사용한다.

```tsx
type Fruit = keyof typeof fruits; // "apple" | "banana" | "blueberry"

const [fruit, setFruit] = React.useState<Fruit | undefined>(undefined);

setFruit("apple");
// setFruit("orange"); // 타입 오류: Fruit 에 없는 값
```

`keyof typeof` 로 타입을 만들면 선택지가 추가되거나 삭제될 때 유니온을 따로 수정하지 않아도 된다. 다만 컴포넌트의 props 가 여전히 `string` 이면 상태 타입과 맞지 않으므로, 컴포넌트에도 같은 관계를 적용해야 한다.

### 제네릭 컴포넌트 만들기

선택지 객체를 제네릭으로 받고, 선택값과 콜백 인자를 그 객체의 키에서 도출한다.

```ts
type OptionKey<O> = Extract<keyof O, string>;

interface GenericSelectProps<O extends Record<string, string>> {
  options: O;
  selectedOption?: OptionKey<O>;
  onChange?: (selected: OptionKey<O> | undefined) => void;
}
```

`options` 에 `fruits` 를 넘기면 `O` 는 그 객체 타입으로 추론되고, 선택값과 콜백 인자도 `"apple" | "banana" | "blueberry"` 로 연결된다. HTML 선택값은 문자열이므로 `Extract` 로 문자열 키만 사용한다.

선택지 객체를 처음부터 `Record<string, string>` 으로 넓혀 선언하면 구체적인 키 정보가 사라진다. **실제 객체의 타입을 유지한 채 제네릭으로 전달해야 한다.**

### HTML 속성 타입 활용하기

Select 에 `id`, `className` 을 추가할 때도 리액트의 기본 요소 타입에서 필요한 속성만 가져온다.

```ts
type NativeSelectProps = React.ComponentPropsWithoutRef<"select">;
type SelectElementProps = Pick<NativeSelectProps, "id" | "className">;
```

HTML 속성 전체를 받으려면 충돌하는 속성은 먼저 제외한다.

```ts
type SelectBaseProps = Omit<
  NativeSelectProps,
  "value" | "defaultValue" | "onChange" | "children" | "multiple"
>;
```

기본 `onChange` 는 DOM 이벤트를 받지만, 여기서 만든 `onChange` 는 선택지 키를 받는다. 그대로 상속하면 서로 다른 의미의 타입이 충돌한다. 단일 선택 컴포넌트라면 `multiple` 처럼 동작을 바꾸는 속성도 함께 검토해야 한다.

### 스타일을 적용하기 위한 타입 활용하기

테마 객체에서 허용할 스타일 키를 추출하고, `Partial` 로 스타일 props 를 선택적으로 만든다.

```ts
const theme = {
  fontSize: {
    small: "14px",
    default: "16px",
    large: "18px",
  },
  color: {
    black: "#000000",
    white: "#FFFFFF",
  },
};

type Theme = typeof theme;

interface SelectStyleProps {
  fontSize: keyof Theme["fontSize"];
  color: keyof Theme["color"];
}

type OptionalSelectStyleProps = Partial<SelectStyleProps>;
```

`fontSize="huge"` 처럼 테마에 없는 값을 막을 수 있고, 테마가 바뀌면 허용되는 키도 함께 바뀐다. 도서에서는 이 타입을 styled-components 에 적용한다. 아래 통합 예제는 타입의 연결을 보기 쉽도록 인라인 스타일을 사용한다.

### 공변성과 반공변성

콜백의 타입을 선언하는 문법에 따라서도 검사 방식이 달라진다.

```ts
type Fruit = "apple" | "banana";

interface CallbackProps {
  onChangeA?: (selected: Fruit) => void; // 함수 속성
  onChangeB?(selected: Fruit): void; // 메서드
}

const onlyApple = (selected: "apple") => {
  console.log(selected);
};

const callbacks: CallbackProps = {
  // onChangeA: onlyApple, // strictFunctionTypes 에서 타입 오류
  onChangeB: onlyApple, // 메서드 문법에서는 허용
};
```

- **공변성**: 타입 사이의 포함 관계가 같은 방향으로 유지된다. 함수 반환 타입에서는 더 구체적인 값을 반환하는 함수를 사용할 수 있다.
- **반공변성**: 포함 관계가 반대 방향으로 적용된다. 함수가 `Fruit` 전체로 호출될 수 있다면 콜백은 `"apple"` 만이 아니라 `"banana"` 도 처리할 수 있어야 한다.
- **이변성**: 매개변수 타입을 양방향으로 허용한다. 메서드 문법은 `strictFunctionTypes` 의 엄격한 매개변수 검사에서 제외되어 위 할당이 허용된다.

메서드 문법으로 오류가 사라져도 런타임에 `"banana"` 가 들어올 가능성은 남아 있다. 콜백 props 는 함수 속성 문법으로 선언하고, 컴포넌트가 전달할 수 있는 값 전체를 처리하게 만드는 편이 안전하다. [타입스크립트 strictFunctionTypes 문서](https://www.typescriptlang.org/tsconfig/strictFunctionTypes.html)
